## Acquisition & Grep Benchmark Framework (FFF vs Ripgrep)

ตามข้อกำหนดใน `SPEC.md` หมวด 12 การประเมินสมรรถนะของ `kept` แบ่งออกเป็น 4 ระดับ:

### 1. Component Benchmark (FFF vs `rg`)
- **Metric:** Search Latency (ms), Match Count, Speed Ratio (kept / rg).
- **Workloads:** Real workspace files on Drive D (`D:\01work\Active\workspace\bl1nk-kept`)
  - Exact identifier match (`Observation`)
  - Function prefix scan (`fn handle_`)
  - Type declaration (`struct ResourceState`)
  - Missing pattern / miss query
- **Baseline:** Official `ripgrep 15.2.0` binary.

### 2. Treatment Benchmark (Judge Token Reduction)
- วัดการประหยัดโทเค็นจริงใน multi-turn AI retrieval loops:
  - Turn 1 (`PASS`): Materialize 100% tokens (~7,466 tokens บน `SPEC.md`)
  - Turn 2–3 (`REFERENCE`): ลดเหลือ 13 tokens pointer (**ประหยัดโทเค็นได้ 99.8%**)
  - Turn 4 (`WARN`): ตรวจจับ loop การอ่านไฟล์ซ้ำเกิน 3 ครั้ง และส่งสัญญาณเตือนเพื่อหยุด infinite loop ของ Agent

## Required comparison discipline

Every new benchmark set must retain raw rows, command/options, input or corpus revision, Rust version/host metadata, run/repetition policy, correctness/safety gate status and limitations. If data contract differs, label comparison `incomparable`; do not calculate a percentage claim from mismatched runs.
