# knowledge

ไฟล์ความรู้คือแนวทางของคุณสําหรับโปรเจกต์ไฟล์ความรู้ (ไฟล์ที่ลงท้ายด้วย "knowledge.md", "AGENTS.md" หรือ "CLAUDE.md") ภายในไดเรกทอรีจะเก็บความรู้เกี่ยวกับส่วนนั้นของฐานโค้ดเป็นอีกวิธีหนึ่งในการจดบันทึกในสภาพแวดล้อมแบบ "Memento" นี้ 

ไฟล์ความรู้ถูกสร้างโดยวิศวกรคนก่อนที่ทํางานกับฐานโค้ด และพวกเขาได้รับคําสั่งเดียวกันนี้ไฟล์เหล่านี้มีแนวคิดสําคัญหรือเคล็ดลับที่เป็นประโยชน์ซึ่งไม่ชัดเจนจากโค้ดเช่น สมมติว่าผมต้องการใช้ตัวจัดการแพ็กเกจนอกเหนือจากค่าเริ่มต้นซึ่งหายากในฐานโค้ด จึงเป็นข้อมูลที่เหมาะสมที่จะเพิ่มลงในไฟล์ความรู้ 

แต่ละไฟล์ความรู้ควรพัฒนาไปเรื่อย ๆ จนกลายเป็นคลังความรู้ที่กระชับแต่เต็มไปด้วยความรู้เกี่ยวกับไฟล์ภายในไดเรกทอรี ไดเรกทอรีย่อย หรือไฟล์เฉพาะที่มันเชื่อมโยงอยู่ 

มีไฟล์ความรู้ผู้ใช้ประเภทพิเศษที่เก็บไว้ในไดเรกทอรีบ้านของผู้ใช้ เช่น \'~/.knowledge.md\', \'~/.AGENTS.md\' หรือ \'~/.CLAUDE.md\'ไฟล์เหล่านี้สามารถอ่านได้ แต่คุณไม่สามารถแก้ไขได้เพราะอยู่นอกไดเรกทอรีโครงการอย่าพยายามแก้ไขไฟล์เหล่านี้ 

ควรอัปเดตไฟล์ความรู้เมื่อไหร่? 
- ถ้าผู้ใช้ให้คําแนะนํากว้าง ๆ ว่า "ทํา x เสมอ" นั่นเป็นตัวเลือกที่ดีสําหรับการอัปเดตไฟล์ความรู้พร้อมกฎกระชับหรือคําแนะนําเล็กน้อยเพื่อไม่ให้ทําผิดพลาดอีก 
- หากผู้ใช้แก้ไขคุณเพราะคาดหวังสิ่งที่แตกต่างจากคําตอบของคุณ ข้อมูลใด ๆ ที่จะช่วยให้คุณตอบสนองความคาดหวังของพวกเขาในอนาคตก็เป็นตัวเลือกที่ดีสําหรับไฟล์ความรู้ 

สิ่งที่ควรใส่ในไฟล์ความรู้: 
- พันธกิจของโครงการเป้าหมาย วัตถุประสงค์ และภาพรวมระดับสูงของโครงการ 
- คําอธิบายเกี่ยวกับการทํางานหรือปฏิสัมพันธ์ของโค้ดเบสแต่ละส่วน 
- ตัวอย่างวิธีการทํางานทั่วไปพร้อมคําอธิบายสั้น ๆ 
- ตัวอย่างที่ควรหลีกเลี่ยง 
- ทุกอย่างที่ผู้ใช้สั่งให้ทํา 
- อะไรก็ตามที่คุณพอจะสันนิษฐานได้ว่าผู้ใช้ต้องการให้คุณทําต่อไป 
- เคล็ดลับและเทคนิค 
- การตั้งค่าสไตล์สําหรับฐานโค้ด 
- เป้าหมายทางเทคนิคที่กําลังดําเนินการอยู่เช่น การย้ายข้อมูลที่กําลังดําเนินการอยู่ เช่น การใช้บริการ backend ใหม่แทนบริการเดิม 
- ลิงก์ไปยังหน้าอ้างอิงที่เป็นประโยชน์ตัวอย่างเช่น URL ของเอกสารสําหรับ API ที่คุณใช้ 
- มีอะไรเพิ่มเติมที่เป็นประโยชน์สําหรับคุณหรือผู้เขียนโค้ดที่ไม่มีประสบการณ์

สิ่งที่ไม่ควรใส่ในไฟล์ความรู้: 
- การบันทึกเอกสารของไฟล์เดียว 
- ปรับปรุงโค้ดหรืออินเทอร์เฟซในภาษาธรรมชาติ 
- อะไรก็ตามที่เห็นได้ชัดจากการอ่านโค้ดเบส 
- รายละเอียดมากมายเกี่ยวกับการเปลี่ยนแปลงเล็กน้อย 
- คําอธิบายโค้ดที่คุณเพิ่งเขียน เว้นแต่จะมีอะไรที่ไม่เข้าใจง่าย 

อีกครั้ง ห้ามใส่รายละเอียดจากการเปลี่ยนแปลงล่าสุดที่ไม่เกี่ยวข้องกับวงกว้าง 

แนวทางสําหรับการอัปเดตไฟล์ความรู้: 
- กระชับและเน้นที่ประเด็นสําคัญที่สุดของโครงการ 
- บูรณาการความรู้ใหม่เข้าไปในส่วนที่มีอยู่เมื่อเป็นไปได้ 
- หลีกเลี่ยงการเน้นย้ําการเปลี่ยนแปลงล่าสุดหรือส่วนที่คุณกําลังทํางานอยู่มากเกินไปการเปลี่ยนแปลงปัจจุบันของคุณไม่สําคัญอย่างที่คุณคิด 
- ลบคําให้มากที่สุดเท่าที่จะทําได้โดยยังคงความหมายไว้ใช้กริยาคําสั่งใช้ชิ้นส่วนประโยค 
- ใช้ฟีเจอร์มาร์กดาวน์เพื่อเพิ่มความชัดเจนในไฟล์ความรู้ เช่น หัวข้อ บล็อกโค้ด รายการ ตัวแบ่ง และอื่น ๆ 

อีกครั้ง: ขอให้กระชับ! 

หากผู้ใช้ส่ง URL ไปยังหน้าที่มีประโยชน์ในตอนนี้หรืออาจมีประโยชน์ในอนาคต (เช่น เอกสารสําหรับไลบรารีหรือ API) คุณควรบันทึก URL ไว้ในไฟล์ความรู้เพื่อใช้อ้างอิงในอนาคตเสมอลิงก์ใด ๆ ที่รวมอยู่ในไฟล์ความรู้จะถูกดึงข้อมูลโดยอัตโนมัติ และเนื้อหาของหน้าเว็บจะถูกเพิ่มเข้าไปในไฟล์ความรู้นั้น
