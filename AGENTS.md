# bl1nk-kept agent handoff

This file is for the next agent session. It is not a product guide or a status report.

## Start here

1. Read `.agents/MEMORY.md` first. Select the Requirement ID being served, inspect every related `MISSING`/`PARTIAL` row, and record the acceptance evidence planned for this session. This is agent-only traceability, not product documentation.
2. Read `TODO.md`. Select the highest-priority unchecked item that satisfies the selected requirement; it is the active product-work source of truth.
3. Read the relevant section of `SPEC.md` before changing a public behavior or boundary.
4. Read `.learnings/ERRORS.md` before implementation. Keep it in the checkout and source handoff; it is agent memory, not product input.
5. Read the related file in `research/`, `schema/`, or `benchmarks/` only when the selected TODO item touches that area.

## Work loop

1. Identify the Requirement ID, exact TODO checkbox, related `MISSING`/`PARTIAL` ledger rows, and behavior that must not regress.
2. Before a public-contract change, obtain the Director's confirmation unless the existing ledger already records an approved contract.
3. Write and run a focused failing test before production code.
4. Implement the smallest change; rerun the focused test.
5. Demonstrate completed user-facing behavior with a real command and observable output. Tests verify code; do not create a persistent artifact only to demonstrate a completed change.
6. Run `just check`, then reconcile every ledger row touched in the session. A row cannot become `COMPLETE` without code path, focused test, command-level evidence, and documentation where public behavior changed.
7. Update the selected TODO checklist and requirement ledger when work state changes. Do not create product task-ticket or completion-report documents.
8. Before packaging or final handoff, verify the archive listing and run `just cli-smoke` from an extracted source archive after any public CLI change.

## Acceptance criteria

Every implementation must follow TDD in this exact sequence: write a red (failing) test, apply the minimal change that makes it pass, rerun the focused test, demonstrate the real behavior with an observable command, then run `just check`. Work is closed only when the matching TODO checkbox is ticked and every public-contract change made in the session is recorded in `CHANGELOG.md`. Internal-only changes are never listed there.

## Repository map

| Path | Meaning | Commands / handling |
|---|---|---|
| `SPEC.md` | Product specification and public boundaries | Change only with Director-approved contract; version line kept in sync by `just version-bump` |
| `TODO.md` | Only work checklist: completed, active, blocked, and planned work | Tick the matching checkbox when closing work |
| `CHANGELOG.md` | Public-contract change history | Append every public-contract change per session; internal-only changes never listed; verified by `just version-check` |
| `plan.md` | Undecided decisions from research that must close before/during implementation | Resolve items here before coding them; move closed decisions to `docs/adr/` |
| `docs/adr/` | Closed architecture decision records | Read before touching a decided boundary; append new ADRs instead of editing old ones |
| `research/` | Retained source-backed research | Read-only input; never edit to fit implementation |
| `schema/` | Generated public registry contract and its generation notes | Regenerate with `just schema`; drift guarded by `just schema-check` |
| `benchmarks/` | Raw comparison data, renderers, and generated benchmark outputs | Chart regenerated by `just benchmark-chart` |
| `CONTRIBUTING.md`, `README*.md`, `get-start.md` | Product/contributor documentation | Update only when public behavior changes |
| `.agents/skills/` | Project-local skills; read the relevant skill before using it | — |
| `.agents/MEMORY.md` | Agent-only directive coverage, evidence and stop conditions; read first | Reconcile touched ledger rows every session |
| `.learnings/` | Agent memory; retain, never expose as product data | Read `.learnings/ERRORS.md` before implementation; keep in checkout and source archive |

Use `just --list` to discover project commands. The next agent must start from the requirement ledger and matching TODO item, not from old reports, snapshots, presentations, or prior chat summaries. A passing test for one new feature never substitutes for reconciliation of earlier Director requirements.
