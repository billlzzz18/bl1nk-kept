# บันทึกการตัดสินใจ 0003: มาตรฐานการเขียนโค้ด Rust ภาษาในเอกสาร และการใช้ Comment Markers

**สถานะ:** ตัดสินใจแล้ว  
**วันที่:** 2026-09-08

## บริบท

ในระหว่างการพัฒนาของ Workspace `bl1nk-kept` มีปัญหาความไม่สอดคล้องเกิดขึ้นหลายประการ:
1. การใช้หัวข้อแบบสองภาษาผสมกัน เช่น `ไทย (English)` ทำให้เกิดความหมายซ้ำซ้อน รกสายตา และอ่านยาก
2. การใส่ comment ภายในโค้ดมีการใช้ marker ผิดรูปแบบ เช่น การใช้ `NOTE-001` ซ้ำทุกจุดโดยไม่รันเลข, การใช้ `// NOTE:` ลอย ๆ ไม่มีหมายเลขกำกับ หรือนำภาษาไทยไปปนใน Rustdoc (`///`) ซึ่งควรเป็นภาษาอังกฤษสำหรับสร้างเอกสาร API สาธารณะ
3. Pre-commit hook เดิมผูกกับ `just check` ซึ่งรัน Full CI/Test ทั้งระบบแม้กระทั่งตอนแก้ไขเฉพาะเอกสาร Markdown ทำให้สูญเสียเวลาและขัดจังหวะการทำงาน
4. ไฟล์ตั้งค่า Markdown Linter มีซ้ำซ้อนกัน 3 ไฟล์ (`.markdownlint-cli2.jsonc`, `.markdownlint.json`, `.rumdl.toml`)

## การตัดสินใจ

`bl1nk-kept` กำหนดมาตรฐานวิศวกรรมและการจัดการเอกสารดังต่อไปนี้:

| มิติ | ข้อกำหนดที่ตัดสินใจ | เหตุผล / ข้อห้าม |
|---|---|---|
| **หัวข้อเอกสารทางเทคนิค** | ใช้ภาษาอังกฤษล้วน กระชับ สื่อความหมายชัดเจน (เช่น `Safety & Error Handling`, `Environment & Tools`) | ห้ามใช้วงเล็บสองภาษาซ้อน `ไทย (English)` เพราะให้ความหมายซ้ำซ้อนและลดความคล่องตัวในการอ่าน |
| **เนื้อหาคำอธิบายในเอกสาร** | ใช้ภาษาไทยเป็นหลักในการอธิบายคู่มือ สถาปัตยกรรม และแนวทางปฏิบัติ | เพื่อให้อ่านเข้าใจง่ายสำหรับทีมและผู้พัฒนา |
| **Public Rustdoc (`///`)** | ใช้ภาษาอังกฤษล้วนสำหรับ Struct, Trait, Function, Public API และ CLI Help | เพื่อให้การ export หรือ build documentation ของ Rust เป็นไปตามมาตรฐานสากล |
| **Internal Code Notes** | ใช้ `// NOTE-001:`, `// NOTE-002:` รันลำดับเลขตามประเด็น โดยเขียนคำอธิบายภาษาไทย | ใช้อธิบายเหตุผลเชิงเทคนิค (Rationale) ที่ไม่ชัดเจน เพื่ออ่านกันเองในทีม ห้ามใช้ `///` ปน |
| **Error Messages ในโค้ด** | ใช้ภาษาอังกฤษล้วนตามมาตรฐานระบบ | รองรับการค้นหา จัดการ error handling และ parse log สากล |
| **Rust Safety Standards** | Zero Panic (`?`, `match`, `if let`), ระวัง `arr.get(i)`, ห้ามกลืน error ด้วย `let _ =`, ห้ามใช้ `mod.rs` | อิงมาตรฐานวิศวกรรม Rust ระดับสากล เน้นความถูกต้อง (Correctness) มาก่อนความเร็ว |
| **Pre-commit Automation** | ใช้ Smart Hook ตรวจเฉพาะ Staged Files (`tools/pre_commit_hook.py`) | ไม่รัน Full CI ทั้งหมดโดยไม่จำเป็น แยก path เอกสารและโค้ดเพื่อความรวดเร็ว |
| **Markdown Configuration** | รวมศูนย์ที่ `.markdownlint-cli2.jsonc` เพียงไฟล์เดียว | ลบไฟล์ซ้ำซ้อนทิ้ง ป้องกัน config drift |
